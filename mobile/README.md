# Wifit3 Mobile 0.4.1 — связка Android ↔ Termux

> Часть набора [wifi-crackd](../README.md): пассивный обзор эфира, авторизованный deauth, сбор hc22000 и отправка хешей на ваш сервер Hashtopolis. Подбор паролей выполняет Hashtopolis, не телефон.

> **Termux:** пользователь подтвердил, что прежняя установка заработала. Для прежней ошибки библиотек сохранён `INSTALL-REPAIR.md`; это инструкция восстановления, а не текущая неисправность.

Мобильный интерфейс для [OliverRhyme/wifit3-termux](https://github.com/OliverRhyme/wifit3-termux): Android-приложение + локальный Python-модуль в Termux. Драйверы работают в Termux, не внутри APK; облако не требуется (Hashtopolis — ваш собственный сервер).

## Запуск Python CLI через uvx

Требуются Python 3.11+, Git и установленный **uv** с командой `uvx`. Пакет ставится прямо из этого репозитория (сабдиректория `mobile`):

```bash
UV='git+https://github.com/ijo42/wifi-crackd.git#subdirectory=mobile'
uvx --from "$UV" wifit3-mobile --version
uvx --from "$UV" wifit3-mobile --demo
```

Откройте локальную ссылку, которую напечатает процесс. Для выхода — Ctrl+C. Базовый пакет не имеет runtime-зависимостей; в DEMO драйверы не импортируются и радио не используются.

Управляемый режим (контроллер создаёт отдельный процесс; после команды start он продолжает работать) и конфиг Hashtopolis из терминала:

```bash
uvx --from "$UV" wifit3-mobile-service start --demo
uvx --from "$UV" wifit3-mobile-service status
uvx --from "$UV" wifit3-mobile-service stop
uvx --from "$UV" wifit3-mobile-htp set --url https://htp.example --token <API-токен>
```

`start`/`status` печатают секретную ссылку — не публикуйте вывод. Локальный uvx cache хранит окружение. **Не очищайте cache и не обновляйте его во время работающей управляемой сессии**; сначала выполните stop.

Для живого USB-обзора на поддерживаемой системе установите extra с закреплённым backend (нужен Git и системный libusb/права на USB):

```bash
uvx --from 'wifit3-mobile[usb] @ git+https://github.com/ijo42/wifi-crackd.git#subdirectory=mobile' wifit3-mobile
```

Первая установка extra скачивает upstream из GitHub. Это не встраивание всего upstream в наш wheel и не предоставление его атак через наш API. Linux-установка `[usb]` через uvx проверена; USB-приём и **uv/uvx именно в Android Termux** в этой среде не проверены. Если uvx не установлен/не поддерживается вашим Termux, используйте уже работающий `bash tools/install-termux.sh` — он не требует uv. APK вызывает фиксированные команды `$PREFIX/bin`; однократный uvx сам по себе такие Android-обёртки не создаёт. Для APK сохранён обычный установщик.

Предпочитаете закреплённую ревизию — добавьте `@<commit>` перед `#subdirectory` (см. `PUBLICATION.md`). Короткая команда `uvx wifit3-mobile` не обещается: пакет не публиковался в Python-индекс.

### Пассивное наблюдение deauth / disassoc

Во время приёма в «Журнале» показываются счётчики и последние **150 принятых** deauthentication/disassociation-кадров: UTC-время, BSSID, source/destination, RSSI, доступный reason code и признак Protected. Они также входят в API state и JSON-экспорт `disconnect_observations`.

Для Protected-кадров reason не читается как открытый текст. Счётчики — число наблюдений, включая возможные повторы; эфирные MAC могут подделываться, а легитимные отключения выглядеть похоже. Это не доказательство атаки или личности отправителя. Переключение каналов/потери приёма могут пропустить события. Новый запуск сканирования очищает счётчики/кольцо, «Стоп» сохраняет последний снимок до новой сессии или завершения процесса. Файл автоматически не пишется — сохраняйте JSON при необходимости.

DEMO-сети не имитируют постоянную атаку: счётчики остаются нулевыми, если не выполняется отдельный тест с синтетической receive-фикстурой.

### Активный deauth (основной сценарий аудита)

Кнопка **«Deauth: форсировать новый хендшейк»** в фокусе сети. Доступна, только когда: (1) при включении дано согласие на аудит, (2) цель подтверждена как WPA/WPA2-PSK, (3) идёт приём. Техника — из upstream: двусторонние deauth-пары каждому наблюдаемому клиенту + broadcast; если у цели PMF required/invalid — только CSA-маяки (нужен захваченный бикон). Автостоп при первом **новом** крэкабельном захвате; живой статус (acks, broadcast, CSA) и итог последней попытки — в карточке кампании и API state (`deauth`). Одновременно одна цель.

**Как в апстриме, кампания фиксирует канал цели:** перебор каналов останавливается, пул встаёт на канал точки доступа, после завершения перебор восстанавливается. Без этого EAPOL-обмен клиента приходил бы, когда приёмник уже на другом канале, и хендшейк не записывался бы. Если после deauth хешей нет — проверьте сигнал до цели, наличие клиентов в фокусе и PMF-статус цели.

Это активная атака: она отключает клиентов от точки доступа. Запускайте только на своих сетях или с письменного разрешения владельца. PMF-цели от deauth не отключаются (по дизайну 802.11w).

### Остановка модуля без Ctrl+C (0.4.1)

В Termux нет кнопки Ctrl — модуль останавливается из интерфейса: вкладка «Модуль» → **«Завершить модуль»** (двойное нажатие для подтверждения). Это аналог Ctrl+C: останавливает deauth/приём, освобождает USB и закрывает локальный сервер. Для управляемого режима дополнительно есть кнопка «Стоп модуль» в Termux-панели APK и команда `wifit3-mobile-service stop`.

### Хеши hc22000 и Hashtopolis (новое в 0.4)

Крэкабельные хендшейки/PMKID сериализуются в hc22000 собственными сериализаторами upstream. Вкладка «Хеши» показывает счётчики по сетям, экспортирует `*.hc22000` (Android — через системный выбор файла, браузер — скачивание) и отправляет хеши на ваш Hashtopolis: батч → hashlist (PLAIN, hashTypeId 22000) + цепочка задач из pretask'ов сервера (по умолчанию — эскалационная цепочка по подстрокам имён; можно все «WPA2 | » или явные id). Dry-run показывает план без отправки; «Проверить связь» делает лёгкий авторизованный запрос.

- Скрытый SSID хеш не даёт (hashcat нечем сверить ESSID). FT-строки (802.11r) hashcat `-m 22000` не брутит — сохраняются как есть.
- В DEMO захват синтетический, помечен `DEMO-` в ESSID, **реальная отправка заблокирована**.
- Конфиг (URL, пользователь, опциональный долгоживущий API-токен) хранится в приватном файле 0600 рядом с `service.json`; пароль и краткоживущий JWT не сохраняются. Из терминала: `wifit3-mobile-htp set|show|clear|test`.
- Отправка передаёт SSID/BSSID/MAC внешнему серверу — учитывайте приватность.

## Сохраняется связка Android ↔ Termux (с 0.2)

Раньше модуль нужно было запускать вручную и копировать код. Теперь в APK есть:

- **«Запустить / подключить Termux»** — фиксированная команда через официальный `RUN_COMMAND` Termux;
- **«Демо без USB»** — отдельный режим без радио;
- **«Проверить и подключить работающий модуль»** — возврат к управляемой сессии;
- **«Остановить модуль Termux»** — остановка приёма, освобождение USB и закрытие локального сервера;
- автоматическое получение кода через одноразовый `PendingIntent` callback и открытие мобильного экрана, без ручного копирования;
- диагностика отсутствующего Termux, отказа разрешения, несовместимого/неустановленного модуля, тайм-аута, занятого порта и разных режимов.

Повторный запуск **не создаёт второй сервер**. Демо/живой режим не переключается за спиной пользователя: сначала нужно остановить модуль. Никакие чужие процессы не завершаются по PID. Ручное подключение по коду сохранено как запасной вариант.

**Статус проверки:** APK собран, подписан тем же debug-ключом, что и версия 0.1; полный набор Python-тестов и браузерный сценарий прошли. Проверены реальные процессы Python и протокол кода/URL. **Android Intent, системный запрос RUN_COMMAND и USB на физическом телефоне НЕ проверены:** устройства/адаптера не было. Не считайте это подтверждённой аппаратной совместимостью. Подробности — `VALIDATION.md`.

## Быстрое обновление с 0.1

1. Остановите старую сессию (кнопкой «Стоп» и `Ctrl+C` в Termux). Не оставляйте ручной сервер на порту 8765.
2. Распакуйте **новый** архив `wifit3-mobile-v0.3.zip` и установите `wifit3-mobile/bin/wifit3-mobile-debug.apk` поверх старого APK. Подпись совпадает, versionCode повышен до 3. Приватный ключ в архив не входит.
3. В Termux из новой папки `wifit3-mobile` повторите `bash tools/install-termux.sh` — без этого старый модуль не поймёт команды новой APK.
4. Для прямой связи выполните `bash tools/enable-termux-link.sh`, прочитайте предупреждение и введите `YES`, если согласны.
5. В APK нажмите «Демо без USB» и выдайте RUN_COMMAND. После проверки остановите демомодуль и запустите обычный режим.

## Первая установка на телефоне

Требуются Android 8.0+, Termux **0.109 или новее** (для результатов RUN_COMMAND), отдельное приложение **Termux:API** из совместимого с Termux источника, USB-OTG и поддерживаемый USB Wi-Fi-адаптер для реального приёма. Одного пакета `termux-api` внутри Termux недостаточно. Для демо USB не нужен.

### 1. Установить Python-модуль

Установите Termux и Termux:API (например, из F-Droid). Положите архив в Download, затем в Termux:

```bash
pkg install unzip
termux-setup-storage
mkdir -p ~/projects
cd ~/projects
unzip ~/storage/downloads/wifit3-mobile-v0.3.zip
cd wifit3-mobile
bash tools/install-termux.sh
```

Установщик после явного YES сначала выполняет apt update / apt full-upgrade с просмотром плана, затем ставит Python/libusb/CLI Termux:API/git/curl (+ опционально hcxtools для офлайн-конвертации pcap), скачивает закреплённую ревизию upstream, устанавливает пакеты в отдельное окружение `~/.local/share/wifit3-mobile/runtime` и создаёт три фиксированные команды в `$PREFIX/bin`:

```text
wifit3-mobile          — ручной сервер с кодом в терминале
wifit3-mobile-service  — управляемый сервер для APK (start/status/stop)
wifit3-mobile-htp      — конфиг Hashtopolis (set/show/clear/test)
```

Root и замена системных Wi-Fi-драйверов не требуются. Для установки нужен интернет, для работы интерфейса — нет. Установщик **не включает** внешние приложения автоматически и не выдаёт Android-разрешения.

### 2. Разрешить прямую связь (необязательно для ручного режима)

В распакованной папке проекта:

```bash
bash tools/enable-termux-link.sh
```

После явного `YES` скрипт устанавливает только свойство `allow-external-apps = true` в `~/.termux/termux.properties` и вызывает `termux-reload-settings`. Другие настройки сохраняются; исходный файл копируется в `termux.properties.before-wifit3-mobile`, если существовал и резервной копии ещё нет.

**Важно:** это общая настройка Termux. В сочетании с разрешением RUN_COMMAND она позволяет доверенному Android-приложению выполнять команды в Termux. ОС не ограничивает это разрешение одной командой. Код Wifit3 Mobile использует только `start/status/stop` собственного модуля, но выдавайте RUN_COMMAND лишь приложениям, которым доверяете.

### 3. Запустить APK

Установите `bin/wifit3-mobile-debug.apk`. Откройте Wifit3 Mobile:

1. Нажмите **«Демо без USB»**, согласитесь на запрос RUN_COMMAND.
2. Если Android не показывает запрос, выдайте разрешение в настройках приложений: Wifit3 Mobile → Разрешения → Дополнительные разрешения → запуск команд в Termux. Название зависит от Android.
3. Приложение получит результат Termux и откроет мобильный экран автоматически. Локальный сервер уже работает, но сканирование ещё не включено.
4. «Адаптер» → обновить список → выбрать DEMO-карту → подтвердить разрешение → начать. DEMO всегда помечен, данные вымышленные.
5. Для настоящего адаптера остановите демомодуль через верхнюю кнопку **«Стоп модуль»**, затем нажмите **«Запустить / подключить Termux»**. Разрешите Android доступ Termux:API к USB, обновите список и выберите карту/диапазон.

Оставляйте сессию Termux открытой; не нажимайте Exit/принудительное завершение во время работы. В зависимости от прошивки может потребоваться отключить ограничения батареи для Termux. Сам APK не гарантирует сохранение фонового процесса при решении Android его завершить. Разрешение «поверх других приложений» для нашего фонового RUN_COMMAND специально не запрашивается.

## Что умеет мобильный экран

Одна USB-карта за сессию; пассивный приём с перебором поддерживаемых каналов 2.4/5 GHz. Сети: SSID/BSSID, канал, сигнал, защита, WPS/PMF-признаки из маяков, производитель, наблюдаемые клиенты, число маяков и время наблюдения. Поиск, диапазон, сортировки, подробности, журнал и JSON-снимок.

**Аудит (0.4):** авторизованный deauth по выбранной PSK-цели (с автостопом по новому захвату), сбор крэкабельных hc22000, экспорт и отправка в ваш Hashtopolis.

**Нет:** EvilTwin/fake AP, WPS-сеансы (Pixie/PBC/PIN), активный PMKID harvesting, WEP recovery, PCAP-запись, подбор паролей на устройстве, несколько карт одновременно. Показ признака WPS в маяке — не запуск WPS. Для остальных возможностей остаётся оригинальный TUI; не запускайте его на той же карте одновременно.

### Две разные остановки

- **«Стоп / освободить USB» внутри мобильного экрана**: прекращает приём, но оставляет локальный сервер для следующей сессии.
- **«Стоп модуль» в Android-панели**: завершает и приём, и управляемый сервер. Соединение закрывается.
- Закрытие APK/отключение интерфейса само по себе не останавливает Termux.
- Остановка модуля удаляет его временные результаты из памяти: сначала экспортируйте нужный JSON.

Команды диагностики в Termux:

```bash
wifit3-mobile-service status
wifit3-mobile-service start --demo
wifit3-mobile-service stop
```

**Вывод status/start содержит секретную локальную ссылку. Не публикуйте его и не присылайте скриншоты с кодом.** APK получает тот же результат через callback, не показывает/не пишет код в журнал.

## Если подключение не получилось

- **Нет ответа за 45 секунд:** результат неизвестен, операция могла завершиться. Проверьте RUN_COMMAND, allow-external-apps, приложение Termux и установленную версию модуля. Затем используйте проверку статуса, не запускайте второй ручной сервер.
- **Команда не найдена / несовместимый модуль:** повторите `bash tools/install-termux.sh` из новой версии архива.
- **Порт 8765 занят:** возможно, работает ручной `wifit3-mobile` из версии 0.1. Остановите его `Ctrl+C` в том терминале либо подключитесь вручную по его коду. APK намеренно не убивает неизвестный процесс и не подбирает его токен.
- **Другой режим уже работает:** остановите модуль, затем выберите демо или живой режим.
- **Нет USB-карты:** проверьте отдельное приложение Termux:API, разрешение Android, OTG, совместимость и питание. После выдачи разрешения повторите обновление через несколько секунд — дескриптор приходит в фоне.
- **Карта отключилась:** «Стоп», переподключить, обновить список, запустить заново. Автовосстановления радиосессии нет.
- **Потеряна связь:** приём может продолжаться; проверьте Termux. Если Android убил модуль, повторное подключение запустит новый, а несохранённый снимок будет потерян.
- Бинарные данные/пароли не извлекаются. Отсутствие сети/клиента в пассивном списке не доказывает их отсутствия. Это не подключение телефона к сети.

### Ручной запасной режим

Если не хотите RUN_COMMAND/allow-external-apps:

```bash
wifit3-mobile --demo   # либо wifit3-mobile для USB
```

В APK выберите «Подключиться вручную по коду» и вставьте код из Termux. Можно открыть напечатанную локальную ссылку в браузере того же телефона. Ручной процесс останавливается `Ctrl+C`; команды управляемого сервиса его не завершают. APK рассчитан на порт **8765**, другие порты — только для браузера.

### Отключить прямую связь

Сначала остановите модуль. Отзовите RUN_COMMAND в Android, установите `allow-external-apps = false` в `~/.termux/termux.properties`, затем `termux-reload-settings`. Это может отключить и другие ваши приложения, которые используют внешние команды Termux. Ручной режим Wifit3 Mobile продолжает работать.

## Сборка APK

JDK 17 + Android SDK Platform 35, Build Tools 35.0.0:

```bash
cd android
./gradlew assembleDebug
# app/build/outputs/apk/debug/app-debug.apk
```

Либо без Gradle (этим путём собран приложенный APK), из корня проекта:

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
bash tools/build-apk.sh
# android/app/build/manual/wifit3-mobile-debug.apk
```

Нужны Python 3 и zip. Используются aapt2/javac/d8/zipalign/apksigner. Debug-ключ создаётся в `~/.android/debug.keystore`, если ещё отсутствует. При самостоятельной пересборке с другим ключом Android не даст поставить обновление поверх старого без удаления. Полная Gradle-сборка в доступном окружении не подтверждена из-за загрузки зависимостей; альтернативная сборка и подпись проверены. Workflow CI включён как исходный файл, не запускался/не публиковался.


Тест `test_upstream.py` требует отдельно установленную закреплённую ревизию `wifit3` и пропускается без неё. `test_service.py` запускает реальные локальные DEMO-процессы на 8765, проверяет жизненный цикл, повторный запуск, права файлов, смену режима и конфликт порта; при уже занятом порте не трогает чужой процесс. Дополнительно проверяются 5 ветвей установщика с заглушками apt/curl/git: отмена, правильный порядок обновлений, сбой apt, неисправный Git HTTPS и режим --check. Эти проверки не являются выполнением apt на Android. На чистом порту с upstream полный набор — **51 тест**.

Браузерный smoke-test: `pip install playwright`, `python -m playwright install chromium`, затем `wifit3-mobile --demo --token-file ./demo-token` в отдельном терминале и `python tools/check-ui.py` из корня. Он останавливает только демоприём, создаёт два DEMO-скриншота и JSON; не используйте с живой сессией. `TOKEN_FILE` задаёт путь к коду, `CHROMIUM_PATH` — свой Chromium; `CONNECTION_URL` позволяет проверить автосопряжение по JSON-ответу контроллера. Не передавайте такую ссылку другим людям.

Для отдельного браузерного теста пассивного журнала установите upstream `[usb]` и playwright, освободите 8765 и выполните `python tools/check-passive-ui.py`. Он использует только фиксированную receive-фикстуру и DEMO, сохраняет `passive-observation-demo.png` и `observation-export.json`. Не запускайте поверх живого сервиса.

## Архитектура и безопасность

```text
Android native buttons (только start / status / stop)
  → permission RUN_COMMAND + явный Intent com.termux.app.RunCommandService
  → фиксированный wifit3-mobile-service
  → управляемый процесс Python, private service.json
  → JSON результата через одноразовый explicit PendingIntent
  → non-exported CommandResultReceiver, проверка nonce/формата/возраста
  → WebView http://127.0.0.1:8765/#код
  → Bearer API → engine.py → upstream WlanInterface / WlanArray → USB
       ├─ deauth: engine → upstream DeauthCampaign (lease канала, PMF→CSA) → TX
       └─ хеши: hc22000-сериализаторы upstream → экспорт / POST на ваш Hashtopolis (HTTPS)
```

Команды не поступают из JavaScript, URL/сети/порты не выбираются произвольным вводом. Receiver не экспортирован; callback одноразовый, привязан к запросу. После паузы приложения результат сохраняется в закрытых настройках до следующего чтения, проверяется возраст (2 минуты), затем удаляется. Резервное копирование APK отключено.

**Исходящий трафик (новое в 0.4):** единственное сетевое исключение из локальности — явная отправка хешей на указанный вами сервер Hashtopolis (`/api/hashes/send`, `/api/htp/test`). URL не проходит чёрные списки; TLS — стандартная проверка сертификатов, без отключений. Токен хранится в приватном 0600-файле рядом с `service.json`, API его не возвращает (`has_token` — только признак наличия); пароль существует только в памяти процесса. В DEMO реальная отправка заблокирована.

Код сервера хранится только в закрытом каталоге Termux `~/.local/share/wifit3-mobile/service` (каталог 0700, служебные файлы 0600), не в Download. Обычный журнал сервиса не содержит токен. Проверяются Host/Origin/Bearer и instance_id. При остановке токен отзывается вместе с процессом и служебный JSON удаляется; после аварийного завершения устаревший файл не даёт права на другой процесс.

WebView не открывает внешние адреса/файлы; JavaScript bridge разрешает только экспорт двух типов документов через системный выбор файла: JSON-снимок и текст hc22000. Приложение объявляет INTERNET (для loopback) и RUN_COMMAND. Не запрашивает root, USB напрямую, контакты, облако, удалённый доступ или произвольное выполнение команд из веб-экрана. Экспорт содержит SSID/BSSID/MAC клиентов — учитывайте приватность.
