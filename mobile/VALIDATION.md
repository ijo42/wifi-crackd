# Проверки Wifit3 Mobile 0.4.2

13 ноября 2026. PMKID/WPS-кампании проверены в DEMO-шимами и юнит-тестами; живой радио-TX не проверялся.

## Выполнено (0.4.2)

- Юнит-тесты: DEMO-PMKID (захват → hc22000 в «Хешах»), DEMO-WPS (PIN найден; отказ на цели без WPS), гейтинг кампаний. Полный браузерный сценарий: три кнопки кампаний в фокусе, статусы «Deauth: …»/«PMKID получен»/«WPS PIN найден: 12345670», фильтры (enc/хеши/клиенты) и сортировка по клиентам — PASS; graceful shutdown PASS.
- Гейтинг live-целей делегирован классам апстрима (`visible`/`ineligible_reason`); на клиенте — приближение по `psk_family`/`rsn_valid`/`hidden`/`wps`/`wps_locked`.
- Body limit 16384 проверен тестами конфиг-эндпоинта (токены >5.4 КБ теперь проходят).

## Не выполнено / ограничения (0.4.2)

- Живой PMKID-harvest и WPS PIN/Pixie на эфире не проверялись (нет адаптера/цели с WPS); код-пути — апстримные кампании без изменений.
- WPS-PSK показывается как есть в UI (приватные данные на вашем устройстве); в Hashtopolis не отправляется (нечего брутить).

# Проверки Wifit3 Mobile 0.4.1

13 ноября 2026. Исправления deauth и новый интерфейс проверены в DEMO и юнит-тестами; живой радио-TX по-прежнему не проверялся (нет адаптера/цели).

## Выполнено (0.4.1)

- **Корень дефекта «deauth виден — хешей нет» найден и закрыт:** в 0.4.0 hop-цикл продолжал работать во время кампании; апстримный Focus-экран перед кампанией делает `stop_hopping` + пин канала цели (`focus_v2/screen.py`), наш мост — нет. Добавлены `_tune_live`/`_restore_hopping` + watcher автозавершения; юнит-тест фиксирует последовательность stop_hopping → set_channel → start_hopping.
- Переработанный UI: браузерный сценарий (check-ui) проходит полностью — фокус цели, живой статус кампании (acks/bcast/CSA → «захват получен»), вкладка хешей, dry-run, блокировка DEMO-отправки, graceful shutdown (сервер действительно завершает процесс; проверено повторным запросом после shutdown).
- JS-краш `null (reading 'psk_family')` устранён (guard в controls()); нативные `confirm()` не используются (в WebView без WebChromeClient они молча возвращают false) — двухшаговое подтверждение.
- 51 тест на Linux с upstream; локально (Windows) 47 passed + 1 skip без upstream, service-тесты — POSIX-only.

## Не выполнено / ограничения (0.4.1)

- Пин канала и восстановление перебора на живом эфире не проверялись (нет адаптера); логика повторяет апстримный Focus-экран и покрыта тестом с фейковым array.
- «Завершить модуль» в Android WebView не запускалось на устройстве (проверено в Chromium).

# Проверки Wifit3 Mobile 0.4.0

13 ноября 2026. Новая функциональность (deauth, сбор hc22000, Hashtopolis) проверена в DEMO и юнит-тестами; живой радио-TX и реальный Hashtopolis-сервер в этой среде не проверялись.

## Выполнено (0.4.0)

- Тесты: деаут-жизненный цикл DEMO (пуск/повторный пуск отклонён/стоп/авто-захват), генерация и сбор DEMO-хешей, `summarize`/`batches`, маскировка конфига Hashtopolis (токен не возвращается API), отказ реальной отправки в DEMO, новые HTTP-эндпоинты (401 без токена, 400 без согласия, сохранение/очистка/маскирование конфига, dry-run), заглушечный Hashtopolis-сервер: JWT-логин, ретрай 401, создание hashlist/task, выбор цепочки pretask'ов.
- Устаревшее поле `passive_only` в state теперь `false`, добавлено `audit: true`; экспорт survey-v1 дополнен `deauth` и `hashes` (формат строки `wifit3-mobile/survey-v1` сохранён — Android-валидация совместима).
- APK 0.4.0 (versionCode 4) с `saveHashes`-bridge: валидация строк WPA*/PMKID* перед сохранением; сборка в CI.

## Не выполнено / ограничения (0.4.0)

- Реальный deauth на эфире: канал-lease, PMF/CSA-ветка, подсчёт acks — только код-путь upstream, физически не проверялся (нет адаптера/цели).
- Отправка на живой Hashtopolis (реальный keyspace-расчёт, агенты) не проверялась; проверен только локальный заглушечный сервер.
- `wifit3-mobile-htp` в Termux не запускался; проверен юнит-тестами на Linux/Windows.
- hc22000-экспорт на Android через системный выбор документа не проверялся на устройстве.

# Проверки Wifit3 Mobile 0.3.0

13 ноября 2026. Публичная публикация не выполнялась: владелец/имя репозитория и доступ не определены. По сообщению пользователя прежняя установка Termux уже заработала; это пользовательское подтверждение, не наш аппаратный тест.

## Выполнено

- **29 Python-тестов**, без пропусков в итоговом прогоне на Linux с закреплённым upstream и свободным локальным портом. Это прежний набор плюс наблюдение deauth/disassoc, Protected/reason, ограничение очереди/потокобезопасность (2000 вызовов), настоящий парсер RX, подключение наблюдателя к интерфейсу и очистка при новой сессии. Тесты не используют радио.
- wheel и sdist 0.3.0 собраны из корневого pyproject; `twine check` проходит. В wheel есть CLI entrypoints, Python-модули, статический интерфейс и LICENSE. Базовый пакет не требует runtime-зависимостей.
- `uvx --from . wifit3-mobile --version` и аналогичная команда контроллера возвращают 0.3.0.
- `uvx --from '.[usb]' wifit3-mobile --version` успешно установил закреплённый upstream и зависимости на Linux. Это не USB-приём.
- Из **собранного wheel** через uvx запущен настоящий отдельный DEMO-процесс без PYTHONPATH checkout: status/start, повторный start с тем же URL, API state, работа UI и JSON-экспорт с disconnect_observations, stop. Всё прошло.
- Установка через **локальный Git VCS URL**, закреплённый commit тестового репозитория без публичного remote, возвращает версию 0.3.0. Это проверка VCS-сборки, не проверка ещё не существующего публичного GitHub URL.
- В Chromium пройдены сопряжение, согласие, DEMO-старт, поиск, карточка, диапазон, JSON, стоп, журнал, неверный код и размеры 390/320 CSS px без переполнения/ошибок JavaScript.
- Отдельная проверка новой функции: фиксированная receive-only тестовая запись → настоящий upstream parser → passive observer → HTTP API → журнал UI и JSON. Показан deauth reason 7, RSSI -51. Скриншот `passive-observation-demo.png` — **синтетический DEMO-тест**, не эфирный захват. Никакие кадры не передавались.
- Android APK обновлён до 0.3.0 (versionCode 3, minSdk 26, targetSdk 35), собран через aapt2/javac/d8/zipalign/apksigner; подпись v2/v3 валидна. Тот же debug key, что в 0.1/0.2; приватного ключа в поставке нет.
- Синтаксис установщика/скрипта opt-in/сборки проверен bash -n. Сохранены 5 black-box проверок установщика с заглушками пакетных/сетевых команд; они не исполняют apt на устройстве.

## Не выполнено / ограничения

- Публикация GitHub, PyPI и запуск GitHub Actions. Имя пакета не резервировалось в Python-индексе; прямой `uvx wifit3-mobile` не обещается. VCS-extra нужно отдельно адаптировать для возможной PyPI-публикации.
- Проверка uv/uvx именно в Android Termux: этот запуск проверен на Linux. Сохранён прежний Termux-установщик без зависимости от uv.
- Установка/запуск новой APK на физическом Android или эмуляторе; системный RUN_COMMAND и PendingIntent callback, системный экспорт JSON, ограничения фонового процесса конкретного телефона.
- USB-разрешение, драйвер, реальный приём deauth/disassoc, потеря/возврат устройства. Без телефона/адаптера подтвердить это нельзя.
- Полная Gradle-сборка: из-за загрузки Java/Maven-зависимостей в доступном окружении не подтверждена. Альтернативная SDK-сборка APK выполнена.
- Пассивный журнал не определяет атакующего: повторы считаются наблюдениями, source MAC может быть поддельным, часть кадров может быть пропущена, legitimate disconnect не равен атаке. Protected reason не интерпретируется.

## Приёмочный тест на телефоне

1. Остановить текущую сессию. Установить APK 0.3 поверх старой и обновить Python-модуль обычным установщиком из нового корня проекта.
2. DEMO → RUN_COMMAND/согласие → автоматический вход → 4 вымышленные сети. В журнале без специального теста deauth/disassoc равны нулю.
3. Стоп модуль, затем обычный режим с разрешённой USB-картой: выбрать карту и разрешение на пассивный обзор. Проверить сеть, журнал и экспорт по мере естественного появления кадров; не создавать помех ради теста.
4. Повторное подключение не создаёт второй процесс; stop освобождает приём. Проверить сворачивание и потерю OTG, учитывая ограничения Android.
5. Для uvx отдельно проверить его доступность на конкретном Termux; сначала `--version` и DEMO, затем extra [usb]. APK по-прежнему требует установленных фиксированных $PREFIX/bin wrapper-команд.

Результат аппаратного теста фиксировать с моделью телефона, Android, версиями Termux/Termux:API и чипсетом адаптера, без токенов/паролей в отчёте.
