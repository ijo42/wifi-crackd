# Исправление установки: libcurl / libngtcp2 / git-remote-https

Исправление установщика от 13 ноября 2026. Это сохранённая инструкция к исправлению установки 0.2. Текущий пакет 0.3.0 включает дополнительные функции; сама ошибка библиотек исправляется обновлением Termux, не пересборкой APK.

## Что означает ошибка

```text
CANNOT LINK EXECUTABLE ... git-remote-https ...
cannot locate symbol "ngtcp2_crypto_get_path_challenge_data2_cb"
referenced by .../libcurl.so
fatal: remote helper 'https' aborted session
```

Android-загрузчик не может запустить HTTPS-помощник Git: установленный `libcurl` ожидает символ, которого нет в загруженной версии библиотеки ngtcp2. Это сильный признак рассогласованных версий пакетов Termux (частичное/прерванное обновление или несинхронное зеркало); точные версии на вашем телефоне не проверялись. Это не ошибка Python-кода приложения, прав USB или GitHub-логина.

Предложения `sv-enable ssh-agent` / `sv-enable sshd` — информационные подсказки другого пакета. **Для установки/работы Wifit3 Mobile включать SSH не надо.**

Предыдущий установщик сразу вызывал `pkg install`, что могло обновить только часть связки библиотек. Исправленная версия сначала предлагает полное обновление Termux через `apt`, показывает план без `-y` и проверяет настоящий Git HTTPS до клонирования.

## Сейчас на вашем телефоне

Остановите работающие сессии Wifit3 Mobile, если есть. В обычном Termux, без root:

```bash
apt update && apt full-upgrade
```

Это обновление **всех пакетов Termux**, не Android целиком. Сначала прочитайте план apt. Если предлагается удаление важных/непонятных вам пакетов, отмените и пришлите план; не подтверждайте вслепую. Существующие пользовательские конфиги не заменяйте без необходимости: при обычном вопросе о сохранении изменённого конфига можно оставить локальный вариант. При ошибке не переходите к следующему шагу.

Почему именно `apt`: обёртка `pkg` может обращаться к сломанному `curl`; разработчики Termux для такого случая рекомендуют `apt full-upgrade` напрямую.

После **успешного** обновления:

```bash
curl --version
git ls-remote --exit-code https://github.com/OliverRhyme/wifit3-termux.git HEAD
```

`git --version` недостаточно: он может работать даже при сломанном `git-remote-https`. Успех второй команды — строка с хешем коммита и HEAD; конкретный хеш не фиксирован. Если обе команды работают, повторите установщик.

Вы были в папке `.../wifit3-mobile/tools`, поэтому для уже распакованного старого проекта команда **из tools**:

```bash
bash ./install-termux.sh
```

А **из корня wifit3-mobile**:

```bash
bash tools/install-termux.sh
```

В новом архиве `wifit3-mobile-v0.3.zip` уже лежит исправленный установщик. Распакуйте его в новую папку, не смешивая файлы старого/нового проекта. Он снова предложит полную синхронизацию — это штатно; если пакеты уже актуальны, apt это сообщит. Также можно проверить без изменений:

```bash
# из корня проекта
bash tools/install-termux.sh --check
```

## Если после полного обновления осталась та же ошибка загрузчика

Переустановите согласованные версии из **настроенного подписанного репозитория Termux**, без произвольных скачиваний .deb:

```bash
apt install --reinstall curl libcurl libngtcp2 git
```

Команда покажет план; подтвердите только понятные изменения. Затем снова `curl --version` и `git ls-remote ... HEAD` из блока выше. Если apt сообщает, что пакет удерживается/недоступен или зеркало не отдаёт пакеты, не снимайте удержания и не заменяйте библиотеки автоматически — пришлите диагностику ниже.

Если `apt update` завершился ошибкой, исправлять клонирование пока рано. Если само `apt` не запускается из-за ошибки загрузчика, команды восстановления зависят от установленной архитектуры/версий; не подбирайте случайные .deb и не очищайте данные Termux.

## Если остался незавершённый каталог upstream

Git обычно убирает неудачный первоначальный clone сам. Если исправленный установщик сообщает, что `~/.local/share/wifit3-mobile/upstream` есть, но не является Git checkout, сначала убедитесь, что это именно каталог этой установки. Не используйте `rm -rf`. Сохраните его под **ещё не существующим** именем, например:

```bash
mv -nT ~/.local/share/wifit3-mobile/upstream ~/.local/share/wifit3-mobile/upstream-before-repair
```

Если резервное имя уже занято, выберите другое; `-n` не перезапишет существующую папку. После перемещения повторите установщик. Новый clone скачивается во временный каталог и становится рабочим только после успешной загрузки/checkout; при сбое данные не удаляются.

## Если не помогло — что прислать

Не переустанавливайте и не очищайте Termux. Пришлите **первую ошибку** `apt update`/`apt full-upgrade` или точный вывод загрузчика и результаты:

```bash
dpkg-query -W curl libcurl libngtcp2 git
apt-cache policy curl libcurl libngtcp2 git
apt-mark showhold
```

Можно добавить `termux-info`, предварительно просмотрев вывод и скрыв личные данные/частные адреса репозиториев. Не присылайте токены подключения, пароли или приватные ключи.

## Чего делать не нужно

- Не запускать sshd/ssh-agent ради этой ошибки.
- Не отключать TLS (`curl -k`, `git http.sslVerify=false`) — отсутствующий символ этим не исправляется.
- Не копировать/симлинковать вручную `.so`, не подменять `LD_LIBRARY_PATH` случайными библиотеками.
- Не удалять данные приложения Termux или домашний каталог.

## Источники и границы проверки

Официальные обсуждения сопровождающих Termux: [почему полные обновления обязательны](https://github.com/termux/termux-packages/issues/17775), [почему при сломанном curl использовать apt напрямую](https://github.com/termux/termux-packages/issues/10871#issuecomment-1755804768). [Рецепт libcurl](https://github.com/termux/termux-packages/blob/master/packages/libcurl/build.sh) указывает зависимость от libngtcp2.

Точная ошибка/установленные версии на вашем телефоне удалённо не воспроизводились. Проверены синтаксис установщика, его ветви с имитацией пакетных команд и сохранение безопасных границ проекта. Реальное восстановление подтвердится успешным curl/Git HTTPS и повторной установкой на вашем устройстве.
